# Native class and script source contract

`py_swf.class_documents.reconstruct_abc_documents(abc, method_sections=None)` returns class and script sections. `reconstruct_class_sections` can restrict work with `class_indices`. The existing method/action inventory remains the source of original bytecode unit identities.

Each section carries `scope`, `class_index` or `script_index`, `completeness`, `unit_ids`, `diagnostics`, and `compiler_eligibility`. A complete class represents its original constructor, static initializer, method/accessor bodies, metadata, interfaces, inheritance, fields, and representable namespace declarations. An unsupported body produces an explicitly partial document with its original unit retained as P-code. It is never substituted with an empty implementation. A legacy outline is always read-only.

Script reconstruction first proves the bootstrap's expression stack, superclass identity, captured hierarchy scopes, namespace URI installations, declaration traits, installation order, and terminal return. Extra executable operations, changed identities, missing installations, and unproven scopes retain P-code. The class source is complete only if every installed class member is complete.

A bootstrap's declarations belong to script/class scope. They never increase method-body source coverage. `decompile_method` returns P-code availability plus a separate-document diagnostic for this case. The optional `include_script_declarations=True` preserves a readable legacy view, labeled `source_kind=script_declarations` and linked by `represented_by_document`. `script_declaration_owner` provides the owner predicate from bytecode and metadata, without inspecting source-looking strings or comments.

## Compiler admission and transactions

Complete reconstruction and editability are separate results. `compile_reconstructed_document(tag, document, source)` accepts a locator from `native_source_documents`. It verifies the original tag SHA-256 and original source SHA-256 against freshly reconstructed current bytes. The original complete script must reproduce the original entire ABC exactly before a class or script replacement is admitted. Declared types, member signatures, namespace identities, class/interface relationships, and metadata must preserve the declaration ABI; method bodies and existing literal field values can change.

The compiler builds the candidate independently, reparses its serialized ABC, and validates every method before returning a replacement tag. The input tag is never mutated. The caller applies the replacement only after its SWF hash/revision guard and full SWF validation pass. Different pool layouts, unsupported source, several original scripts, external unresolved providers, or incomplete members keep the reconstructed document read-only.

The shared native compiler accepts several package blocks, additional source files, declared explicit namespace URI aliases and qualified members (`this.ns::value`), normal inheritance/interfaces/overrides, and ordered class initialization blocks. A bare class block represents static initializer code. Reference `coerce` uses a typed local assignment; it is never rewritten as `as` or a type function call. Primitive declared returns can absorb their identical numeric/boolean conversion. Nullable string conversion is preserved independently; `String(null)` and a nullable String assignment are not interchangeable.

Construction of `Error`, `TypeError`, `RangeError`, `ReferenceError` and `SyntaxError` requires the immutable local playerglobal SWC contract with its pinned SHA-256. The provider must be the exact blank public QName, the Error base must reach the intrinsic Object root, and the constructor argument count must match the SDK declaration (zero through two arguments in the pinned SDK). Missing/changed SDKs, ambiguous declarations, interfaces, unproven parents and lexical/member/catch/closure shadows fail before bytecode is returned. This is a bounded constructor provider, not a general external API linker or support for extending external Error classes.

Native AVM2 branch labels use opcode `label` rather than `nop`. In particular, loop backedges must target a dedicated label for player verification. The two opcodes have the same execution-side effect, while the dedicated marker satisfies the player's branch-entry rule. AVM1 branch markers are unchanged.

## Namespace and scope identities

Private identities include the original ABC constant-pool scope and namespace index. A matching printable URI does not link two private identities. Protected access requires a uniquely declared class hierarchy. Internal access requires the exact owner package. Explicit namespace member source uses a declared URI alias; unresolved alias names remain P-code. `super` uses the exact inherited trait QName. Attribute QNames are not converted into normal field declarations.

The reserved expression qualifier `public::name` selects an empty public namespace, without inventing a namespace declaration or selecting a same-named private member. Public package types used by class signatures, fields, bases and interfaces have deterministic imports. Unsupported type namespaces, ambiguous import names, and member or parameter names that shadow source type annotations make a document partial instead of emitting source with different binding semantics.

Numeric and Boolean bytecode conversions use operators (`+(value)`, `value | 0`, `value >>> 0`, and `!(!value)`) so a member named `Number`, `int`, `uint` or `Boolean` cannot replace the intrinsic operation. Generated temporaries preserve conversion execution before later effects even when the result is discarded. String conversions retain their distinct nullable behavior and remain P-code when the required type name is shadowed.

Script declaration proof compares the full captured ancestor sequence, including order and multiplicity. External ancestry is accepted only from the immutable, SHA-256 verified local playerglobal SWC metadata contract; an absent or changed SDK contract cannot supply a guessed hierarchy. Native instance methods capture the declaring class object after the declaration scopes, matching the outer-scope indices used by activation closures.

`AbcSymbolIndex` snapshots index method owners, bodies, class names, namespaces, and hierarchy resolution. NativeBackend and class reconstruction reuse one immutable snapshot per ABC. A worker iterating immutable units can attach `abc._native_symbol_index = AbcSymbolIndex([abc])` once and pass it to `source_edit_reason(..., symbol_index=...)`. Mutating/editing guards create a fresh index by default. A complete class/script compilation proof is attempted once for a single-script ABC, never once per member of a large application.

## AVM1 and exception recovery

AVM1 control flow carries constant-pool identities on each edge. Incompatible pools at a merge or exception entry retain P-code instead of choosing one arm. Nested functions capture the definition-time pool. DefineFunction2 checks its register count, preload allocation, parameter bindings, reserved flags, and suppressed variable lookup. Reassigned preloaded registers use hygienic locals; lexical suppression that source cannot preserve remains unsupported.

Nested Flex exception regions that share an entry remain separate regions. Enclosing completion rewrites are visible when recognizing an inner finally's completion trampolines. Forwarding catches cannot accidentally acquire a later unrelated finally dispatch. Crossing regions, unsupported anonymous catch-all layouts, scope mismatches outside proven exception resets, and ambiguous activation/register state retain P-code.

## Evidence and limits

`tests/test_parity_class_documents.py` validates complete/partial documents, private and explicit namespace identity, ordered static initialization, exact original ABC admission, stale-source rejection, declaration protection, serialized candidates, and changed method results. `tests/test_parity_scopes_regions.py` covers AVM1 pool/register/suppression negatives and compares original versus recompiled traces, returns, errors, and raised state for twelve cases of a real three-level Flex finally method.

These tests are bounded evidence for the existing VM subset. They do not establish whole-player Flash/Ruffle parity, unrestricted AS3 linking, or equivalence for every number and object domain. The subset's null/undefined representation limitation remains explicit. Ruffle/player checks and frozen cohort gains are recorded separately by the integration workflow; no binary was replaced by these source changes.

The final selected native regression run contains 355 passing cases. The development closure project produced `PARITY_CLOSURE_10` through both shared-native and independent Flex compilation in Ruffle. The native atomic fixture in `reports/parity-implementation-20261014/runtime-fixtures/native-atomic` proves exact-original ABC admission, full candidate validation, and the intended trace edit from `7` to `11`; the integration owner recorded each Ruffle result against its separate expected trace. Those player checks are finite fixtures, not unrestricted source equivalence.

The Error-constructor development follow-up is recorded separately in `reports/error-constructors-20261014`. The generated class from `dev-as3-control-handlers` now compiles through both the shared native compiler and independent Flex, and both reconstructed programs produce the exact expected `PARITY_HANDLER_11` trace in the pinned headless Ruffle harness. The initial native candidate exposed VerifyError #1021; its report is retained, and the dedicated AVM2 label regression covers the discovered cause. The new constructor tests also execute four bounded loop/catch/finally paths in the test VM and check constructor QName, arity, argument order and shadow/provider rejection. These are finite development checks; they do not prove general AS3 semantic parity or reserved-set blindness for this iteration.

After these changes, the complete current Python test suite passed 1132 cases with one skip (`reports/error-constructors-20261014/full-pytest.log`). The native control candidate's own read-back still marks its calculation partial (`Overlapping regions at 74`) and retains exact P-code. Its successful compilation and runtime trace do not imply that every layout produced by the native compiler can already be reconstructed as editable source.
